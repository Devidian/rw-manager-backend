# Manager backend 0.9.0

This stable release includes the accepted duplicate-reconciliation RCs. The Steam super-admin can review strong and possible catalog matches, preview affected favorites and statistics, and confirm a merge into the oldest server ID. Former IDs resolve to the canonical record. Candidate groups require at least one online instance and exclude the default Rising World server name.

Overlapping statistic hours keep the strongest online observation and all observed player UIDs. New alias requests record statistics under the canonical ID. In-flight catalog and query refreshes cannot recreate source records removed by a merge. The public RC test restored the confirmed server's history to 455 hours, 436 with online evidence, and removed six stale alias records; later checks found no returning aliases or alias buckets.

Requires MongoDB replica-set transactions and the existing `SUPER_ADMIN_ID`. Deploy before Manager frontend 1.9.0. Back up MongoDB before deployment and before real merges. Reverting the image cannot restore a wrongly merged or deleted record; use the MongoDB backup for data rollback.

Validation: backend RC.3 passed the TypeScript build, 50 Jest suites, 235 tests, the configured coverage gate and GitHub CI. The public RC.3 backend was healthy with zero restarts; old-ID statistics resolved to the canonical ID.
